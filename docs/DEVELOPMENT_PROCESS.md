# 轻量级 AI 长篇创作平台详细开发流程

> 文档版本：v0.4  
> 修订日期：2026-09-13  
> 对比基准：OpenFic 仓库（<https://github.com/syrizelink/OpenFic>，发布前重新核对）。  
> 目标：用可控的迭代方式完成一个功能强于 OpenFic、但默认运行更轻量的 Windows AI 小说创作平台。  
> 建议周期：16～20 周完成 Windows 1.0；单人开发可按 24～32 周执行。Windows 1.0 只验收 Windows 10/11 x64，PWA、多人协作和其他平台不作为首发阻塞项。

## 1. 开发原则

1. 先跑通内容闭环，再增加 Agent 数量和高级检索。
2. 每个阶段都有可演示版本和验收条件。
3. 数据模型、API 契约和导出格式先稳定，UI 可以持续调整。
4. 所有 AI 写入先生成 operation preview，再由用户提交。
5. 默认功能不依赖外部基础设施；可选模块通过接口隔离。
6. 每周至少完成一次真实长篇项目回归测试。

## 2. 团队角色

单人开发时可由同一人兼任；Windows 首发按单用户本地工作区设计，多人协作仅保留接口，不纳入首发验收。多人时建议拆分：

- 产品/架构：需求、领域模型、发布决策。
- 后端：API、数据库、AI、检索、任务。
- 前端：编辑器、助手、资料库、交互状态。
- QA/工程：测试、构建、迁移、性能和安全。

## 3. 产品领先验收原则

每项功能都必须回答三个问题：是否比 OpenFic 更容易理解，是否比 OpenFic 更安全地修改内容，是否在没有额外基础设施时仍可运行。

功能优先级分为：

- **P0 闭环**：编辑、上下文、Prompt、AI 预览、版本和导出。
- **P1 领先**：故事图谱、确定性约束、伏笔闭环、批量审稿、主备模型切换。
- **P2 扩展**：自动模型路由、跨设备离线合并、插件 OS 级沙箱、向量检索和专家工作流。

每个 P1/P2 功能都要有一组真实小说数据回归样例，不能只用 mock 数据验收。

### 3.1 项目初始化（第 1 周）

0.1 的目标是编辑、单 Provider、Prompt、上下文、AI 预览、版本和导出闭环。故事图谱、时间线、伏笔、批量审稿和跨设备离线合并不得挤占 0.1 的验收范围；如需提前建表，只建立最小 schema 和迁移占位。

### 3.2 建立仓库

```bash
mkdir novel-workbench
cd novel-workbench
git init
mkdir backend frontend docs scripts
```

建立分支策略：

- `main`：可发布代码。
- `develop`：集成分支（单人项目可省略）。
- `feat/*`：功能开发。
- `fix/*`：问题修复。

提交格式：`feat(scope): subject`、`fix(scope): subject`、`docs(scope): subject`。

### 3.3 固定基础工具

后端：uv、Ruff、Pytest、Pyright；中文分词默认可选 jieba，未安装时使用 n-gram 回退。  
前端：pnpm、ESLint、Prettier、Vitest、Playwright；样式使用 CSS Modules。 
桌面端：Windows 11/10、Rust stable、Tauri 2、cargo test、tauri build。  
CI 首先只做：安装、格式检查、类型检查、单元测试、前端构建。

### 3.4 输出物

- 架构决策记录 ADR-001：为什么默认 SQLite。
- ADR-002：为什么默认 SSE。
- ADR-003：正文 operation 和 revision 规则。
- 本地开发 README。
- `.env.example` 和数据目录说明。

验收：新机器可以按 README 在 10 分钟内启动前后端，并创建空项目。

## 4. 领域模型与数据库（第 2～3 周）

### 4.1 先实现的实体

按顺序实现：`Project → Volume → Chapter → Revision → Entity → Note`。

每张表完成：

- SQLAlchemy 2 模型。
- Alembic migration。
- Repository。
- Service。
- Pydantic request/response schema。
- API 集成测试。

### 4.2 版本和操作

先实现三种操作：

1. 替换选区。
2. 在章节末尾插入。
3. 恢复指定 revision。

所有操作都必须检查目标版本哈希。冲突时返回 409，并把服务端当前内容和客户端预期内容同时返回。

### 4.3 验收

- 创建、重命名、排序和删除项目/章节。
- 保存正文后可以查看历史。
- 恢复历史后，正文、字数和更新时间一致。
- 重启服务后数据完整。
- 导出 JSON 后可通过导入接口恢复。

## 5. 故事图谱基础接口（第 3～4 周，P1 预研）

### 5.1 实体和事实

只实现统一实体、别名、状态快照、来源引用和事实确认的最小 schema、Repository 和迁移。AI 提取的事实先进入待确认区，用户确认后才能成为项目事实。完整 UI、影响分析和规则校验在第 11 周资料库阶段实现。

### 5.2 时间线和伏笔

预留事件、绝对/相对时间、伏笔生命周期和证据链接的数据接口；暂不实现完整图谱 UI 和规则校验。

### 5.3 验收

- 迁移可以创建并回滚最小实体、事件和伏笔表；
- 待确认事实与已确认事实有明确状态；
- API 契约测试通过，且不影响 0.1 编辑闭环。

## 6. 前端编辑器与内容树（第 4～5 周）

### 6.1 页面优先级

1. 项目列表。
2. 写作工作区：左侧树、中间编辑器、右侧助手。
3. 资料库：角色、地点、组织、规则。
4. 历史版本。
5. 设置页。

### 6.2 编辑器要求

- 自动保存，显示保存状态。
- Markdown 粘贴和导出。
- 选区坐标稳定，操作后保留光标。
- 大章节使用虚拟化或分段加载。
- 离线时进入本地草稿状态，Windows 1.0 只保证本地持久化和强制关闭后的恢复；联网后的自动提交与跨设备合并列入 1.x。

### 6.3 验收

- 断网输入不会丢失。
- 同一章节连续编辑 100 次不会生成异常重复 revision。
- 选中一段文字后能看到 AI 操作入口。
- Windows 桌面窗口可以完成打开、编辑和保存；开发浏览器的窄屏布局作为非阻塞回归项。

## 7. Provider 与 AI 流式调用（第 5 周）

### 7.1 Provider 抽象

先只实现 OpenAI-compatible；接口稳定后再增加 Anthropic-compatible、Gemini 和本地模型。Windows 桌面端固定使用 PyInstaller one-dir 生成 Python Sidecar，Tauri 只负责生命周期管理，用户不需要预装 Python。

实现内容：

- Provider CRUD。
- API Key 加密存储。
- 模型列表手动配置和远程探测。
- 超时、重试、取消。
- token 使用量记录。
- 错误标准化。

### 7.2 SSE 流程

```text
创建 session
  → 提交 user message
  → 构建 ContextPackage
  → 调用 provider.stream
  → 推送 delta/tool/progress
  → 写入 assistant message
  → 生成 operation preview
```

必须支持：客户端取消、服务端超时、断线重连、重复提交幂等。长任务写入 SQLite jobs 表，服务重启后可恢复。

### 7.3 验收

- 能配置一个兼容 OpenAI API 的模型并流式返回。
- 关闭浏览器后重新打开可以看到完整消息。
- 模型超时不会把章节写入半成品。
- API Key 不出现在 API 响应和普通日志中。

## 8. 系统提示词管理

### 8.1 提示词数据结构

实现 `prompt_templates` 和 `prompt_versions`，字段至少包括：

- `scope`：global、project、agent、workflow、session；
- `owner_id`：项目、Agent 或工作流 ID；
- `content`：Markdown 提示词正文；
- `variables`：变量名称、类型、是否必填；
- `enabled`、`version`、`created_by`、`created_at`。

### 8.2 合并和渲染

按“全局 → 项目 → Agent → 工作流 → 会话临时”顺序合并。渲染器只允许白名单变量，缺失必填变量时阻止调用并给出明确错误。正文、检索结果和网页内容统一包裹为不可信数据区，并在 Prompt 中明确禁止其改变系统规则或触发工具。所有模板修改生成新版本，不直接覆盖历史版本。

### 8.3 前端功能

- 系统提示词管理页；
- 项目提示词和 Agent 提示词分栏；
- 变量帮助和模板示例；
- 实际发送给模型的最终提示词预览；
- token 估算、版本对比和恢复；
- 当前会话临时指令编辑。

### 8.4 验收

- 修改项目提示词不会影响其他项目；
- 禁用某个 Agent 提示词后回退到默认版本；
- 变量渲染结果可在调用前预览；
- 任意 AI 消息都能追溯到系统提示词版本；
- 恢复旧提示词后，新调用使用旧版本，历史调用保持不变。

## 9. 上下文构建与基础工具（第 6～7 周）

### 9.1 上下文优先级

固定顺序：用户指令 > 当前选区/章节 > 项目规则 > 相关实体 > 时间线/伏笔 > 检索结果 > 历史摘要。

每个片段携带：来源、优先级、token 数、是否可截断、展示标题。

### 9.2 首批工具

- `read_chapter`。
- `search_project`。
- `read_entity`。
- `create_note`。
- `propose_text_operation`。
- `update_entity`（审批后执行）。

工具输入使用 Pydantic schema，所有工具结果带 `success`、`error_code` 和 `source_ids`。

### 9.3 验收

- 前端可以展开查看 ContextPackage。
- 上下文超过预算时按优先级截断，并说明原因。
- 工具错误会被模型和用户清楚看到。
- AI 只能生成 operation preview，不能绕过服务层直接改正文。

## 10. FTS5 检索与引用（第 8 周）

### 10.1 实现顺序

1. 应用侧中文分词、字符 n-gram 回退和拼音字段。
2. 章节和实体全文索引。
3. 标题、别名、标签过滤。
4. 当前项目和当前卷范围过滤。
5. 高亮片段。
6. 召回结果来源跳转。
7. 可选向量接口和混合排序（非阻塞扩展，未安装时必须保持 FTS5 完整可用）。

### 10.2 中文验证集

建立至少 50 条真实查询：角色别名、事件描述、专名、同义表达、伏笔线索、跨章节回忆。记录命中章节和排名，作为回归数据。

### 10.3 验收

- 10 万字项目索引和查询在目标机器上可接受。
- 每条 AI 引用都能定位到章节和段落。
- 无向量依赖时系统仍完整可用。
- 索引失败可重试且不会破坏正文。

## 11. 资料库界面与创作联动（第 9～10 周）

### 11.1 资料库

实现资料库 UI 和章节联动：名称、别名、描述、属性、标签、来源章节、状态。实体变更进入 revision，并触发相关章节重新索引；修改实体时显示受影响章节。

### 11.2 时间线

支持绝对时间、相对顺序和未知时间。事件必须能关联章节和实体。提供列表视图优先，图视图后置。

### 11.3 剧情分支

实现最小分支对象：名称、父分支、触发条件、关联章节和状态。先提供列表和章节跳转，图形化分支视图列入后续版本。

### 11.4 伏笔

状态流转：`draft → planted → developing → resolved | abandoned`。AI 只能建议状态变化，用户批准后提交。

### 11.5 验收

- 角色改名可以维护别名并影响检索。
- 时间线可按章节和故事时间排序。
- 剧情分支可创建、编辑、关联章节并从章节跳转。
- 伏笔有埋设和回收证据。
- 连贯性检查能指出无来源的冲突候选。

## 12. AI 操作事务与质量评测（第 11 周）

### 12.1 操作事务

将文本修改、实体修改、伏笔状态变化和批量修改统一为 operation。每个 operation 包含目标版本哈希、预览 diff、权限级别、幂等键和撤销操作。

### 12.2 质量评测

建立 30～50 个固定评测样例，覆盖续写、改写、设定问答、冲突检查和摘要。记录人工评分、引用准确率、token、耗时和成本。

### 12.3 验收

- AI 结果不能绕过 operation 服务直接写库；
- 并发修改返回明确冲突；
- Prompt 或模型升级前后可比较评测结果；
- 被拒绝的 operation 不改变正文和故事图谱。


## 13. 批量审稿、创作分析与备用模型（第 12～13 周）

### 13.1 批量审稿

实现规则检查、LLM 检查、证据报告、暂停/恢复和导出。报告只生成建议，不自动覆盖正文。

### 13.2 创作分析

实现节奏、角色出场、对话比例、视角切换、重复表达和伏笔回收率统计。先做列表和趋势图，图谱视图后置。

### 13.3 备用模型与评测

按任务声明上下文需求，支持一个主模型和一个备用模型的失败转移。建立固定评测集，比较 Prompt/模型变更前后的输出。Windows 1.0 不做基于成本和质量的自动路由，自动路由列入 1.x。

### 13.4 验收

- 20 个章节可批量运行并恢复；
- 每个问题包含证据和位置；
- 模型故障能切换备用配置；自动模型路由列入 1.x；
- 服务重启后批量审稿、索引和导出任务可继续；
- 评测结果包含质量、token、耗时和成本。

## 14. 工作流与专家助手（第 13～14 周）

### 14.1 工作流最小模型

```text
input → context → llm → parser → approval? → operation → output
```

节点类型：Prompt、LLM、检索、条件、人工审批、写入、导出。每次运行保存输入快照、节点状态、输出和错误。

### 14.2 内置工作流

- 章节计划：目标 → 冲突 → 场景卡 → 验证。
- 章节初稿：场景卡 → 相关设定 → 草稿 → 审稿。
- 连贯性检查：章节 → 时间线/实体 → 问题列表 → 证据。
- 章节摘要：正文 → 摘要 → 角色/事件提取。

### 14.3 验收

- 工作流失败可以从失败节点重试。
- 审批前不会写入正文。
- 批量运行 20 个章节时可暂停和恢复。
- 专家助手输出能回到主会话并保留来源。

## 15. 导入导出与备份（第 15 周）

实现：

- Markdown 文件夹导入。
- JSON 全量备份。
- ZIP 项目包。
- DOCX/EPUB 导出。
- 附件校验和。
- schema version 和迁移脚本。

导出包默认不包含 API Key、会话令牌或其他密钥；导入采用临时目录解包、清单校验和事务提交，失败时不改变现有项目。

验收：从导出包删除 SQLite 数据库缓存后，仍可使用包内的 JSON 清单和正文文件恢复项目，章节、实体、版本和附件引用一致；导入失败时不改变现有项目。

## 16. 安全、性能和可观测性（第 16 周）

### 16.1 安全检查

- 默认 localhost。
- 显式 CORS allowlist。
- 远程模式的密码认证、安全 Cookie 和 CSRF 防护；localhost 模式使用短期本地令牌。
- API Key 加密及脱敏日志。
- 路径遍历、任意文件读取、SSRF、Prompt 注入测试。
- 外部工具权限审批。

### 16.2 性能检查

- 10 万字和 100 万字测试数据集。
- 中文分词、n-gram、拼音和专名检索对比基准。
- 首屏加载、章节打开、保存、搜索、SSE 延迟。
- SQLite WAL、索引和 vacuum 策略。
- 大附件和长章节的内存占用。

### 16.3 数据流向和可观测性

每次调用外部模型、Embedding、Rerank 或网页搜索前，界面显示将发送的数据范围。默认本地日志；遥测关闭。提供诊断导出，用户主动下载后再分享。记录请求 ID、任务 ID、模型耗时、token 和错误码，不记录正文、Prompt 和 API Key。

## 17. 测试计划

### 17.1 后端

- 领域服务单元测试。
- API 契约测试。
- migration 从空库升级测试。
- operation 冲突和恢复测试。
- Provider mock 流式、超时、取消、重试测试。
- 检索回归测试。

### 17.2 前端

- 编辑器保存状态和本地离线草稿恢复测试。
- SSE 重连和重复事件测试。
- 选区操作预览和撤销测试。
- 资料库、时间线和版本页面测试。

### 17.3 E2E 主路径

1. 创建项目。
2. 创建角色和世界观。
3. 创建章节并写入正文。
4. 配置模型。
5. 选区改写并审批。
6. 搜索资料并跳转引用。
7. 恢复历史版本。
8. 导出并重新导入。

## 18. 离线同步与插件隔离（第 17 周）

### 18.1 离线草稿与后续同步

Windows 1.0 只保证本地离线草稿持久化和恢复。跨设备操作队列、网络恢复后的提交和 old_hash 三方合并属于后续版本，先保留接口和数据格式。

### 18.2 插件隔离

插件声明权限、输入输出 schema 和版本。插件只能调用工具 API，不能直接访问 SQLite 文件或密钥。

### 18.3 验收

- 断网编辑不会丢稿；
- 本地草稿在强制关闭后可恢复；跨设备冲突合并列为后续版本验收；
- 禁止权限的插件无法读取正文；
- 插件通过 JSON-RPC 进程边界访问工具 API；这不等同于 OS 级安全沙箱；
- 卸载插件不影响项目数据。

## 19. 轻量桌面端（Tauri 2，第 18 周）

### 19.1 实现顺序

1. 开发用浏览器完成离线草稿缓存和 localhost API 配置；PWA 独立交付不属于 Windows 1.0 验收。
2. 创建 Tauri 2 宿主，只加载前端静态资源。
3. Rust 启动随安装包提供的 Python Sidecar，传入随机端口和数据目录；开发环境可直接调用虚拟环境 Python，不能作为发布依赖。
4. 增加单实例锁、优雅退出、崩溃重启和日志目录。
5. 接入系统文件选择器、通知、托盘和自动更新。
6. 在 Windows 10 和 Windows 11 上执行启动、编辑、导出和退出测试。

### 19.2 轻量桌面验收

- 不捆绑 Chromium；
- 首次启动能自动启动本地后端；
- 关闭窗口后后台服务可以按策略退出；
- 安装包大小和空闲内存记录在发布报告中；
- 无 WebView2 时给出明确安装提示，并提供微软官方运行库链接；
- 桌面端与开发用浏览器共用同一套前端代码和 API；PWA 作为后续交付形态单独验收。

## 20. Windows 首发交付规范（第 18～19 周）

### 20.1 支持范围

- Windows 10 22H2 及以上；
- Windows 11；
- 首发架构为 x64；
- ARM64 作为后续版本，不进入首发验收；
- 安装包使用 Tauri 2 + WebView2 + Python Sidecar；
- 用户不需要预装 Python、Node.js 或 Rust。

### 20.2 Windows 数据与运行目录

- 应用程序目录：`%LocalAppData%\\Programs\\NovelWorkbench`；
- 用户数据目录：`%LocalAppData%\\NovelWorkbench\\data`（避免漫游目录承载大型作品）；
- 日志目录：`%LocalAppData%\\NovelWorkbench\\logs`；
- 临时目录：使用 `%TEMP%` 下的应用专属子目录；
- 支持在设置中选择自定义数据目录，并在切换前执行完整性检查和备份。

### 20.3 Windows 安装与更新

1. Tauri 启动时检查 WebView2，并在缺失时显示安装引导；
2. 启动 Python Sidecar，随机分配 localhost 端口；
3. 使用命名互斥体保证单实例；
4. 安装包提供 NSIS 安装器和便携 ZIP；
5. 更新采用签名安装包，下载后校验 SHA256 和签名；
6. 更新前自动备份 SQLite 数据库和版本元数据；
7. 更新失败时保留旧版本并支持恢复备份。

### 20.4 Windows 首发验收

- Windows 10/11 全新环境可安装并启动；
- 无 Python 和 Node.js 时仍可运行；
- WebView2 缺失时提示清晰；
- 安装、卸载、升级不会删除用户数据；
- 断电或强制关闭后数据库可恢复；
- 文件选择器、剪贴板、通知、托盘和开机启动可用；
- x64 安装包、便携 ZIP 和 SHA256 文件均可生成。

## 21. 发布流程

### 21.1 发布前

- 更新版本号和变更日志。
- 执行后端 lint/type/test。
- 执行前端 lint/type/test/build。
- 构建 Docker、Python wheel 和 Windows Tauri 桌面包；PWA 构建作为后续交付的可选产物。
- 在干净数据目录启动并执行 E2E。
- 用旧版本数据执行升级迁移。
- 检查导出包和回滚方案。

### 21.2 发布渠道

- Docker 镜像：`latest` 和固定版本 tag。
- Python 包：仅用于服务端和开发者。
- 桌面版：首发提供基于 Tauri 2 的 Windows x64 安装包，后续再增加其他平台。
- 每个发布产物附 SHA256。

### 21.3 回滚

应用代码可回滚，数据库迁移必须提供可逆或备份恢复方案。发布前自动复制数据库和数据目录元信息；迁移失败时禁止继续启动写入。

## 22. 迭代节奏

每周固定完成：

- 周一：确定本周可验收目标。
- 周二至周四：实现和测试。
- 周五：真实作品回归、性能检查、整理 CHANGELOG。
- 周末或下一周开始：发布内部版本并记录问题。

每个功能必须有：需求说明、API/schema 变更、测试、截图或录屏、已知限制。

## 23. 风险清单

| 风险 | 应对 |
|---|---|
| LLM 输出不稳定 | 结构化 schema、重试、审批和 operation 校验 |
| 长上下文成本高 | 摘要层级、token 预算、引用优先级和缓存 |
| 中文检索效果不足 | FTS5 验证集、别名/拼音字段、可选 embedding |
| SQLite 并发受限 | 单写入队列、WAL、短事务、明确单机定位 |
| AI 覆盖用户修改 | old_hash 乐观锁、冲突 409、版本恢复 |
| 依赖快速升级 | 锁文件、适配器、定期升级分支和回归测试 |
| 数据丢失 | 自动备份、全量导出、导入演练、迁移前快照 |
| 公网误部署 | localhost 默认、密码提示、启动安全检查 |
